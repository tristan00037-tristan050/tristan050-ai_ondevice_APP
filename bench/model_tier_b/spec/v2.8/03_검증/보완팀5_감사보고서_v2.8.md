# 보완팀5(온디바이스) v2.7 감사 및 v2.8 교정 보고서

## 판정

`SPEC_REVIEW_PASS=YES`, `CODE_IMPLEMENTATION_PASS=NO`, `M3_START_ALLOWED=NO`다. 첨부물에는 실제 저장소, full Git OID, CI 원본, trust root, M3 raw가 없으므로 코드·성능 완료를 확인할 수 없다.

## 확인 사실

- v2.7 자체 집계: 후보 패키지 3종 점수 45·54·42, P0 28건, P1 18건, 공격시험 11건 중 우회 10건, M3 sample 0건.
- 결함표 46행 모두 `blocking_gate=M3_START`다.
- 본문은 P0 28건 폐쇄 뒤 M3를 허용하는 표현이 있어 결함표와 충돌한다.
- DOCX는 CI를 10-job으로, 교정 MD는 12-job으로 표기해 단일 정본이 아니다.
- “signed attestation”, “OS egress controller”, “worker nonce/self-hash”, “모든 binary scan”의 신뢰경계와 실패조건이 충분히 닫히지 않았다.

## v2.8 강제 결정

1. 46개 결함 전부를 M3 시작 차단으로 통일한다. P0는 merge·M3 차단, P1은 M3 readiness 차단이다.
2. 승인 정책은 canonical JSON 정본으로 고정한다. YAML은 strict parse 후 변환하는 편집 입력일 뿐이다.
3. 서명은 trust root·issuer·identity·repository·workflow·ref·commit·subject digest를 검증한다.
4. inner `release.tar.gz`를 서명하고 bundle과 함께 outer handoff ZIP에 넣는다. 자기 자신을 포함한 ZIP의 자기서명 주장은 금지한다.
5. worker nonce는 freshness 증거로 한정하고, 승인 executable provenance·parent timing·stream digest·model/runtime identity를 결속한다.
6. macOS egress는 실증된 Network Extension, 전용 사용자 OS deny controller, 외부 deny-all network 중 승인 프로필만 허용한다.
7. 등록 binary만 magic/MIME/schema/digest/size를 검증하고, archive bomb 한도와 다중 encoding secret scan을 적용한다.
8. Git LFS pointer blob과 materialized object 무결성을 분리한다.
9. CI는 12-job으로 통일하고 signed attestation replay를 마지막 필수 job으로 둔다.
10. 검증된 전력 계측원 없이는 joule 수치를 만들지 않는다.
