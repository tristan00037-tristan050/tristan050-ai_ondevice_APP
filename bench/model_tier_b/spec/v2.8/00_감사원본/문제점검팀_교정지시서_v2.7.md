# Butler 모델티어 B v2.7 교정 개발지시서

## 0. 목적

v2.7은 새 기능 추가가 아니라 v2.5~v2.6의 신뢰 경계와 실행 증거를 닫는 교정 릴리스다. 아래 P0가 하나라도 남으면 `CODE_PASS=NO`, `M3_START_ALLOWED=NO`다.

## 1. 단일 기준 revision

1. 승인 저장소 URI, base commit/tree, effective product commit/tree, harness commit/tree를 full OID로 고정한다.
2. clean committed worktree만 허용한다.
3. fetch 가능한 PR/ref 또는 git bundle을 제공한다.
4. LFS object와 submodule을 포함해 source blob→archive file 등가를 전수 검증한다.
5. CI가 발행한 signed in-toto/SLSA attestation에 revision, policy, test artifact를 결속한다.

### 종료 조건

```text
SOURCE_REVISION_VERIFIED=1
CLEAN_COMMITTED_TREE=1
BLOB_ARCHIVE_EQUIVALENCE=1
SIGNED_SOURCE_ATTESTATION=1
```

## 2. 승인 정책

1. YAML duplicate key를 차단한다. 가능하면 승인 정본은 canonical JSON으로 고정한다.
2. policy에는 approver identity, approval scope, expiry, fixture/model/tokenizer/runtime/evaluator/controller/worker digest를 포함한다.
3. boolean gate를 저장하지 말고 각 gate의 receipt digest를 저장한다.
4. policy digest 생성 후 immutable snapshot을 사용한다.

## 3. 실제 Box3 product path

1. 실제 production endpoint에 observer hook을 삽입한다.
2. primary draft는 동일 프로세스의 `VolatileDraft`에서만 유지한다.
3. soft allowlist에서만 4B repair 정확히 1회.
4. hard/DLP/policy/approval/model/asset failure는 repair 0회.
5. primary와 repair 모두 evidence parse→grounding→unsupported labeling→style→human approval→DLP→final gate를 통과한다.
6. authoritative final event는 DLP 이후 정확히 한 번 생성한다.
7. primary/repair/cascade/final receipt는 request, input, model, output, stage trace digest로 완전 결속한다.

## 4. worker reality binding

1. parent가 nonce와 expected identity를 worker에 전달한다.
2. worker는 executable, runtime config, model files를 직접 hash한다.
3. model load 전, inference 직전, 종료 후 hash/identity를 재검사한다.
4. parent가 request write와 첫 실제 byte/token을 monotonic clock으로 관측한다.
5. stdout/stderr를 동시에 bounded drain한다. stream별 4 MiB 이하, event별 64 KiB 이하.
6. timeout 시 process group TERM→KILL 후 descendant PID 0을 증명한다.
7. synthetic event-only worker는 통과할 수 없도록 output digest와 tokenizer count를 실제 stream에 결속한다.

## 5. OS egress

1. owner runner가 controller lifecycle을 소유한다.
2. controller type은 승인 enum만 허용한다.
3. controller binary hash와 서명을 검증한다.
4. target process group과 모든 child/descendant를 정책에 등록한다.
5. activation interval이 전체 worker/sampler/evaluator 구간을 덮어야 한다.
6. native IPv4, IPv6, DNS, HTTPS, subprocess probe를 별도 프로세스에서 수행한다.
7. OS packet/firewall counters와 denied transcript digest를 독립 verifier가 재계산한다.

## 6. memory·Metal·environment·dual resident

1. 승인 sampler binary가 8개 mark와 일정 주기 raw-safe sample을 수집한다.
2. PID set은 owner의 process tree에서 계산한다.
3. RSS, available memory, memory pressure, swap, Metal current/recommended를 기록한다.
4. macOS build, chip, physical memory, CPU count, Metal registry ID, thermal, LPM, AC power를 epoch 전후에 기록한다.
5. 1.7B와 4B는 distinct manifest/variant/PID여야 한다.
6. 두 worker의 model-loaded interval과 실제 inference interval overlap을 verifier가 계산한다.
7. 양쪽 inference count, OOM=0, sampler error=0, policy bypass=0을 원시 transcript에서 계산한다.

## 7. evidence와 독립 verifier

1. artifact에 receipt 0개를 허용하지 않는다.
2. artifact profile별 mandatory receipt types와 final pointer를 schema로 고정한다.
3. 모든 파일을 scan한다. 확장자/NUL을 이유로 skip 금지.
4. 허용 binary는 명시된 MIME·schema·digest만 허용한다.
5. verifier는 producer package를 import하지 않는다.
6. 그러나 단순 structure 검증에 그치지 않고 다음을 재계산한다.
   - receipt DAG, duplicate/orphan/cycle
   - terminal order와 single final
   - worker FSM, parent timing, model identity
   - schedule와 warmup exclusion
   - memory gap/peak/PID scope
   - egress interval/probes
   - dual overlap/inference
   - live semantic result와 evaluator identity
   - final status와 9 gate
7. verifier output은 `STRUCTURAL_PASS`와 `SEMANTIC_PASS`를 분리한다.

## 9. M3 canonical run

1. 5 epoch
2. candidate별 epoch warmup 2회, metrics 제외
3. fixture×candidate×epoch measured 2회
4. physical order repetition1 AB, repetition2 BA
5. epoch cooldown 실제 15초 이상
6. epoch 전후 thermal nominal/fair, LPM false, AC power
7. fixed seed와 schedule digest
8. p50/p95, paired bootstrap 95% CI
9. failure/repair/cascade rate
10. RSS/Metal/swap/energy/joules per request
11. instrumentation overhead paired negative control
12. samples-first independent verification
